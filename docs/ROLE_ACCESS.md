# Роли: соответствие техническому заданию

Источник: `dokum/ТЗ_Контроль_ремонта_квартиры.docx`, разделы 3.2, 4.1.1, 4.2, FR02–FR05, FR07, FR09–FR12, приложение А. Сценарии уточняются документом `dokum/USE_CASE_Контроль_ремонта_квартиры.docx`, UC-4–UC-13.

## Что должно различаться

| Действие | Заказчик | Прораб | Исполнитель | Текущая реализация |
|---|---|---|---|---|
| Изменить реквизиты своего проекта | Да | Нет | Нет | Проверка на сервере и в интерфейсе |
| Добавить и удалить участников, назначить роль | Да | Нет | Нет | Проверка на сервере и в интерфейсе |
| Создать и редактировать этапы, назначить ответственного | Да | Да | Нет | FR04: общие права намеренно сохранены |
| Удалить собственный этап-черновик без зависимостей | Да | Да | Нет | Ограничение раздела 4.12 |
| Просмотреть этапы и команду | Да | Да | Да | Только внутри доступного проекта |
| Создать и назначить задачи | Да | Да | Нет | Ещё не реализовано, этап 40% |
| Выполнить назначенную задачу | Нет | Нет | Да | Ещё не реализовано, этап 40% |
| Передать этап на приёмку | Нет | Да | Нет | Ещё не реализовано, часть Бекзата 40% |
| Принять этап, подтвердить устранение замечаний | Да | Нет | Нет | Ещё не реализовано, часть Бекзата 40% |
| Создать и редактировать смету | Да | Да | Нет | Ещё не реализовано, этап 60% |
| Утвердить смету, её изменения и расходы | Да | Нет | Нет | Ещё не реализовано |
| Запустить проект | Да | Нет | Нет | Требуются принятый прораб и утверждённая смета; пока не реализовано |
| Завершить проект | Да | Нет | Нет | Требуются приёмка всех этапов и закрытие замечаний; пока не реализовано |

Дополнения этапа 40% (задачи, фотоотчёты, приёмка и замечания) описаны в [MILESTONE_40.md](MILESTONE_40.md). Ниже сохранено описание базового этапа.

## Роль относится к проекту

В ТЗ, раздел 3.2, одному пользователю разрешены разные роли в разных проектах. Поэтому глобального переключателя «стать прорабом» или общей роли аккаунта нет. Пользователь может быть прорабом в проекте А и создать собственный проект Б, где станет заказчиком. Создание нового проекта не даёт ему прав заказчика в проекте А.

На странице списка проектов это явно названо «Создать свой проект как заказчик». В существующем проекте права всегда определяются записью ProjectMember. Проверки не зависят от заголовка кабинета, переданных полей формы или отображения кнопок.

## Приглашение прораба

По разделу 4.2 и UC-6 прораб должен принять приглашение. Поэтому добавление по email или из сохранённого контакта создаёт приглашение для прораба, даже если его аккаунт подтверждён. До принятия доступа к проекту нет. Нельзя обойти этот порядок прямой сменой роли исполнителя на прораба.

Для исполнителей сохранено согласованное с владельцем проекта упрощение: подтверждённый пользователь добавляется сразу по email или контакту. Для неизвестного/неподтверждённого email создаётся приглашение. Сценарий явного приглашения через API также сохранён. Контакты принадлежат добавившему их заказчику и доступны ему для повторного выбора.

## Планирование и жизненный цикл

FR04 разрешает обеим управляющим ролям создавать и изменять этапы. Это не даёт права произвольно менять состояние приёмки. По приложению Б цикл этапа: «Запланирован → В работе → На приёмке → Принят».

Ранее упрощённые кнопки «Начать работы» и «Работы выполнены» обходили условия запуска проекта. Они удалены, а изменение статуса через сервис редактирования и API отклоняется. В форме этапа остались данные планирования; новые этапы всегда запланированы. Отдельные действия запуска, передачи на приёмку и приёмки должны быть реализованы вместе с их проверками и зависимыми модулями, а не заменены переключателем статуса.

Ранее сохранённые этапы и их статусы не удаляются и не переписываются. Статус completed оставлен для совместимости с существующими данными, но новые переходы в него через редактирование запрещены.

## Интерфейс текущего этапа

- Заказчик: сведения о квартире, управление командой, состояние приглашения прораба, просмотр плана и сроков. Самостоятельное добавление этапа доступно отдельным раскрывающимся блоком.
- Прораб: планирование этапов, порядок работ, список этапов без сроков или ответственного. Состав команды и реквизиты проекта доступны для просмотра.
- Исполнитель: просмотр плана и команды без действий управления.
- Входящие приглашения отображаются только их получателю на главной и в списке проектов.

Файлы регистрации и входа `apps/accounts/` этой корректировкой не изменяются. Новые проверки ролей находятся в тестах projects, repairs и workspace.
