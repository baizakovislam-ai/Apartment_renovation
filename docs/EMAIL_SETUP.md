# Подтверждение регистрации по коду

При регистрации программа отправляет шестизначный код на указанный адрес. Без подтверждения войти нельзя. Код действует 10 минут и используется один раз. После пяти неверных попыток нужно запросить новый код. Повторная отправка доступна через 60 секунд, максимум пять писем в час на аккаунт. Новый код отменяет предыдущий. В базе хранится только HMAC кода, без самих цифр.

## Подключение Gmail

1. Для Gmail отправителя включите двухэтапную проверку и создайте пароль приложения на странице [паролей приложений Google](https://myaccount.google.com/apppasswords). [Инструкция Google](https://support.google.com/mail/answer/185833?hl=ru) описывает условия доступности этой функции.
2. В корне проекта заполните локальный файл `.env`:

```dotenv
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_HOST_USER=your-address@gmail.com
EMAIL_HOST_PASSWORD=your-app-password
```

`EMAIL_HOST_PASSWORD` — пароль приложения, не обычный пароль аккаунта Google. Пароль сохраняется только локально; `.env` исключён из Git. Пробелы между группами символов пароля приложения можно оставить. Адрес отправителя используется также для восстановления пароля. Сервер `smtp.gmail.com`, порт 587 и TLS соответствуют [настройкам Gmail SMTP](https://support.google.com/a/answer/176600?hl=ru).

3. После изменения `.env` перезапустите сервер:

```powershell
.\venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

4. Откройте `/accounts/register/`, заполните имя, email и пароль. На следующей странице введите код из полученного письма. При успешном подтверждении откроется вход.

Если аккаунт уже был создан, повторно регистрироваться не нужно. Откройте `/accounts/resend-verification/`, укажите его email и получите код. Это также помогает аккаунтам, зарегистрированным до перехода со ссылок на коды.

При отсутствии настроек или отказе SMTP программа показывает ошибку отправки. Неудачная новая регистрация не сохраняет незавершённый аккаунт. При неудачной повторной отправке ранее выданный код остаётся действительным до окончания своего срока. Принятие письма SMTP-сервером не гарантирует его появление во входящих: проверьте также папку «Спам».

## Проверка трёх ролей на обычном проекте

Достаточно трёх обычных подтверждённых аккаунтов с разными email. Создайте проект первым аккаунтом — он станет заказчиком. Через вкладку «Команда» пригласите второй аккаунт прорабом; приглашение нужно принять во втором аккаунте. Третий аккаунт добавьте исполнителем. Роли назначаются в проекте, а не при регистрации.

Новые тестовые аккаунты и демонстрационные проекты автоматически не создаются. Имеющиеся аккаунты, проекты и приглашения сохраняются.
