# Этап 40% (срок — 15 ноября 2026)

Объём взят из таблицы распределения работ в ТЗ (строки «20%» и «40%»):

| Требование ТЗ | Что сделано |
|---|---|
| FR02 Управление проектами (хвост 20%) | Адрес, площадь, сроки, бюджет, описание, статус проекта. Карточка «О проекте», редактирование заказчиком, удаление собственного черновика без этапов и задач. |
| FR05 Задачи и контроль сроков | Создание, правка, удаление задач заказчиком и прорабом. Исполнитель — участник с ролью «Исполнитель», срок — в пределах дат этапа. Статусы: К выполнению → В работе → На проверке → Выполнена, возврат на доработку с причиной. Отметки «Просрочена» и «Скоро срок» (2 дня), фильтр просроченных. |
| FR06 Фотоотчёты | Описание, автор, дата, 1–8 фото JPEG/PNG/WebP до 8 МБ. Тип проверяется по содержимому (Pillow), фото пересохраняются без метаданных (EXIF/GPS). Файлы лежат в `media/private/` и отдаются только участникам с доступом к задаче. |
| FR08 Прогресс ремонта | Процент выполнения проекта и каждого этапа, счётчики задач, просрочек и этапов на приёмке. |
| FR07 Приёмка работ и замечания | Прораб передаёт этап на приёмку, заказчик принимает или возвращает с причиной. Замечания с ответственным и сроком, ответы в ветке, «Устранено» → проверка заказчиком. Открытые и устранённые, но не проверенные замечания блокируют приёмку. |
| FR17 (частично) | Поиск и фильтры задач (текст, статус, этап, просрочка) и замечаний. |
| FR20 | Все действия пишутся в историю проекта. |

## Правила

* **Видимость.** Заказчик и прораб видят все задачи и замечания. Исполнитель — только назначенные ему задачи и замечания, без бюджета и страницы приёмки. Чужие проекты и фото отдают 404.
* **Запуск работ.** Задачу можно начать, когда этап в статусе «В работе». Кнопка «Начать этап» на странице этапов. С этапа 60%: этапы начинаются только после утверждения сметы и запуска работ заказчиком (см. docs/ISLAM_PART.md, раздел 6).
* **Приёмка.** Передать этап может только прораб, если все задачи этапа выполнены и нет нерешённых замечаний. Замечание к этапу на приёмке автоматически возвращает его в работу. Решение, автор и время сохраняются (`StageDecision`).
* **Прогресс.** Принятый этап = 100%. До приёмки этап даёт до 90% по доле подтверждённых задач. Процент проекта — среднее по неотменённым этапам.
* **Надёжность (ТЗ 4.13).** Задачи и замечания имеют счётчик `version`: устаревшая форма получает ошибку, чужие изменения не теряются. Формы создания несут `request_id` (UUID): повторная отправка возвращает уже созданную запись. Кнопки блокируются после первого нажатия. Операции выполняются в транзакции с блокировкой строки проекта.
* **Удаление.** Удалить можно только свою задачу, к которой не приступили и у которой нет фотоотчётов и замечаний. Этап с задачами удалить нельзя. Участника с задачами или замечаниями нельзя удалить или сменить ему роль.

## Демонстрация для трёх ролей

```powershell
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py seed_demo          # чистая база: аккаунты + полный демо-проект
.\venv\Scripts\python.exe manage.py seed_milestone40   # если демо-проект уже был создан раньше
```

Аккаунты: `customer@example.com`, `foreman@example.com`, `executor@example.com`. В проекте «Демонстрационный ремонт»:

* «Демонтаж» — принят заказчиком.
* «Электромонтаж» — задачи во всех статусах, одна просрочена, есть открытое замечание.
* «Штукатурка стен» — задачи выполнены, прораб может передать этап на приёмку.
* «Чистовая отделка» — запланирован.

Сценарий проверки:

1. **Исполнитель.** В «Мои задачи» открыть «Установить подрозетники», добавить фотоотчёт и передать на проверку. В «Замечаниях» ответить и нажать «Устранено».
2. **Прораб.** Подтвердить «Собрать электрощиток». В «Приёмке работ» передать «Штукатурку стен» заказчику.
3. **Заказчик.** Принять «Штукатурку стен», проверить рост процента. Закрыть устранённое замечание или вернуть его с причиной.

## API

Аутентификация — сессия Django с CSRF. Все адреса начинаются с `/api/`.

| Метод и адрес | Назначение |
|---|---|
| `GET, PATCH, DELETE projects/{id}/` | Проект: просмотр, изменение (заказчик), удаление проекта без рабочих записей |
| `POST, DELETE projects/{id}/archive/` | В архив (`reason`) / вернуть из архива |
| `DELETE projects/{id}/members/{member_id}/?replacement=<id>` | Удалить участника, передав незавершённую работу |
| `GET invitations/`, `POST invitations/{token}/decline/` | Мои приглашения / отклонить |
| `GET, POST projects/{id}/tasks/` | Список (фильтры `q`, `status`, `stage`, `assignee`, `deadline=overdue`) и создание задачи |
| `GET, PATCH, DELETE tasks/{id}/` | Задача. PATCH и DELETE требуют актуальный `version` |
| `POST tasks/{id}/action/` | `action`: `start`, `submit`, `approve`, `return`; `version`; `text` — результат или причина возврата |
| `GET, POST tasks/{id}/reports/` | Фотоотчёты. POST — multipart: `description`, `images` (несколько), необязательный `request_id` |
| `GET projects/{id}/progress/` | Прогресс проекта и этапов |
| `GET, POST projects/{id}/remarks/` | Замечания (фильтры `q`, `status`, `stage`). Создаёт заказчик: `stage`, `description`, `responsible`, `due_date`, необязательные `task`, `request_id` |
| `GET, PATCH remarks/{id}/` | Замечание / правка автором или заказчиком (`description`, `responsible`, `due_date`, `version`) |
| `POST remarks/{id}/action/` | `action`: `reply`, `fix`, `close`, `reopen`, `withdraw`; `text`; `version` (кроме `reply`); фото — multipart `images` |
| `GET, POST stages/{id}/acceptance/` | GET — блокеры и решения. POST `action`: `submit` (прораб), `accept`, `return` с `reason` (заказчик) |

Создание задачи: `stage`, `name`, `assignee` (ID участия ProjectMember), `due_date` (`YYYY-MM-DD`), необязательные `description`, `request_id`.

Фото выдаются по адресу `/files/photos/{id}/` после проверки доступа. Путь в хранилище наружу не отдаётся. Каталог `media/private/` нельзя публиковать веб-сервером.

## Вне этапа 40%

Смета и её согласование, изменения сметы, расходы (60%). Прайслисты и предварительный расчёт (80%). Email-уведомления, итоговый PDF, завершение проекта (100%). Фотографии самого проекта (FR02) пока не загружаются: фото прикладываются к задачам.

## Доработка 27.10.2026

Участник удаляется без потери истории: незавершённую работу передают другому, выполненная остаётся за ним, его можно пригласить снова. Прораб приглашает исполнителей, приглашения приходят на почту и видны на «Главной». Проект с работой отправляется в архив, без работы — удаляется. Замечания получили отдельную страницу, фото, правку и снятие; их может оставлять и прораб. Этап без задач на приёмку не передаётся. Подробности и проверка по шагам — [ISLAM_PART.md](ISLAM_PART.md) и [BEKZAT_PART.md](BEKZAT_PART.md).
