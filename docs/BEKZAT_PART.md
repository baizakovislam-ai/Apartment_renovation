## Как запустить

* **Только на своём компьютере:** двойной клик по `start.bat` в корне проекта. Откроется http://127.0.0.1:8001/.
* **С доступом для других из той же Wi-Fi сети:** `start_lan.bat`. Адрес для других будет показан в окне сервера.

Демо-аккаунты (пароль у всех `RepairDemo2026!`): `customer@example.com` — заказчик, `foreman@example.com` — прораб, `executor@example.com` — исполнитель. Проект «Демонстрационный ремонт».

Что подготовлено в демо для проверки приёмки:

| Этап | Состояние |
|---|---|
| Демонтаж | Принят заказчиком, видно решение и фото |
| Электромонтаж | Не все задачи выполнены, есть открытое замечание, поэтому приёмка заблокирована |
| Штукатурка стен | Все задачи выполнены, прораб может передать этап на приёмку |
| Подготовительные работы, Чистовая отделка | Запланированы |

## 1. Управление проектами (20%)

### 1.1. Создать проект

**Кто:** любой вошедший пользователь. Создатель автоматически становится заказчиком.

**Как проверить:**
1. «Мои проекты» → «Создать проект».
2. Обязательно только название. Необязательные поля: адрес, площадь (м²), начало и окончание ремонта, лимит бюджета (сом), описание.
3. После сохранения сразу откроется страница проекта с блоком «Что сделать дальше»: пригласить прораба, добавить этапы, пригласить исполнителей, создать задачи, начать работы. Выполненные шаги зачёркиваются.

**Проверка полей** (каждое должно дать ошибку):
* Пустое название.
* Площадь 0 или меньше.
* Отрицательный бюджет.
* Дата окончания раньше даты начала.

### 1.2. Просмотр проекта

Откройте проект → «О проекте». На странице видно:
* Паспорт объекта: адрес, площадь, сроки, бюджет, автор.
* Описание.
* Прогресс ремонта и прогресс по этапам.

Под исполнителем бюджет **не показывается**: по ТЗ у исполнителя нет доступа к финансам.

### 1.3. Редактировать проект

**Кто:** только заказчик. Прораб и исполнитель кнопки не видят, а прямой адрес `/projects/<id>/edit/` вернёт 403.

**Как проверить:** «О проекте» → «Редактировать» → изменить поля → «Сохранить». Изменение попадёт в «Историю изменений»: что было и что стало.

### 1.4. Удалить проект или отправить в архив

**Кто:** заказчик, создавший проект. Внизу страницы «О проекте» всегда есть блок с двумя действиями. Он не пропадает, а объясняет, что можно сделать.

**Удалить проект** (безвозвратно) можно, пока в проекте нет рабочих записей: задач, фотоотчётов, замечаний и решений по приёмке. Команда, приглашения и этапы без задач удаляются вместе с проектом — блок заранее пишет, сколько людей потеряют доступ. Если удалять нельзя, вместо кнопки написана причина, например «в проекте есть задачи, этапы уже передавались на приёмку».

**Отправить в архив** можно всегда, нужно указать причину. По ТЗ 4.12 рабочие записи не стираются, поэтому проект с выполненной работой «удаляется» в архив:
* он пропадает из «Мои проекты» и с «Главной»;
* в «Мои проекты» появляется ссылка «Архив (N)»;
* внутри всё доступно для просмотра, но изменять ничего нельзя — сверху жёлтая плашка;
* «Вернуть из архива» на странице «О проекте» возвращает всё как было.

**Как проверить:**
1. Создайте проект, пригласите кого-нибудь, добавьте этап без задач → «Удалить проект» → проект исчезнет.
2. В проекте с задачами вместо кнопки удаления будет причина. Введите причину в «Отправить в архив» → проект уйдёт в «Архив».
3. Откройте его из архива → «Вернуть из архива».

### 1.5. Поиск проектов и текущий проект

* В «Мои проекты» есть поиск по названию и адресу. Новые проекты — сверху. Видны только проекты, где вы сейчас в команде. Чужой проект по прямой ссылке вернёт 404.
* Система запоминает проект, с которым вы работаете: «Главная» открывает его, а не самый старый.
* После входа в аккаунт сразу открывается «Главная» с проектами и приглашениями (раньше открывался профиль).

## 2. Приёмка работ (40%)

Страница «Приёмка работ» в меню проекта. Её видят заказчик и прораб. Исполнитель её не видит, а прямой адрес вернёт 403.

Для каждого этапа на странице показаны:
* статус и прогресс;
* чек-лист: сколько задач выполнено и сколько нерешённых замечаний;
* список нерешённых замечаний;
* последние фотоотчёты этапа (клик открывает фото);
* история решений: кто и когда передал, принял или вернул этап.

### 2.1. Передать этап на приёмку

**Кто:** только прораб.

**Как проверить:**
1. Войти прорабом → «Приёмка работ» → у «Штукатурки стен» нажать «Передать на приёмку».
2. Статус этапа станет «На приёмке», в решениях появится «Передан на приёмку» с именем и временем.

**Блокировка:**
* Этап без задач передать нельзя: «В этапе нет ни одной задачи — нечего принимать».
* У «Электромонтажа» кнопки нет. Вместо неё написано «Передать нельзя: Не выполнено задач: 3; Открытых замечаний: 1».
* Заказчик не может передать этап сам: кнопка есть только у прораба.

### 2.2. Принять этап или вернуть на доработку

**Кто:** только заказчик.

**Как проверить:**
1. Войти заказчиком → «Приёмка работ» → у этапа «На приёмке»:
   * «Принять этап» → статус «Принят», процент проекта вырастет.
   * Или «Вернуть на доработку» → обязательно указать причину → статус «В работе».
2. Решение, автор и время сохраняются в «Решениях» и в «Истории изменений».
3. Повторное нажатие не создаёт второе решение.

### 2.3. Блокировка приёмки при открытых дефектах

* Если к этапу на приёмке создать замечание, этап **автоматически возвращается в работу**.
* Пока есть замечание «Открыто» или «Устранено, ждёт проверки», этап нельзя ни передать, ни принять.
* Принятый этап больше нельзя редактировать.

## 3. Замечания (40%)

Раздел «Замечания» в меню проекта. Вверху вкладки «Открыто / Ждёт проверки / Закрыто» со счётчиками. Каждое замечание открывается на отдельной странице: описание, фото дефекта, переписка с фото, история и кнопки действий.

| Роль | Что видит и может |
|---|---|
| Заказчик | Все замечания. Создаёт (прорабу или исполнителю), редактирует и снимает свои, подтверждает устранение любого замечания |
| Прораб | Все замечания. Создаёт исполнителям, подтверждает устранение своих замечаний, может отметить «Устранено» за исполнителя |
| Исполнитель | Только замечания, где он ответственный. Отвечает с фото и отмечает «Устранено» |

### 3.1. Создать замечание

**Кто:** заказчик или прораб. Кнопка «Новое замечание» в разделе. Есть быстрые ссылки: «Оставить замечание» в карточке задачи и на «Приёмке работ» — этап и задача подставляются сами.

**Поля формы:**
* этап;
* задача — необязательно, список задач по этапам;
* «Что не так»;
* «Кто устраняет»: заказчик выбирает прораба или исполнителя, прораб — только исполнителя;
* срок устранения;
* фото дефекта — до 8 штук, JPEG/PNG/WebP.

**Что должно запрещаться:**
* Срок в прошлом.
* Этап, который ещё не запущен или уже принят. В форме будет подсказка: «Запустите этап — после этого к нему можно оставлять замечания».
* Задача из другого этапа.
* Исполнитель создаёт замечание: прямой адрес вернёт 403.
* Двойной клик: создаётся только одно замечание.

Если этап был на приёмке, замечание автоматически возвращает его в работу.

### 3.2. Устранение и подтверждение

1. **Исполнитель** открывает замечание. Пишет комментарий, при желании прикладывает фото результата и нажимает «Устранено». Можно сначала просто «Ответить».
2. Статус становится «Устранено, ждёт проверки». В блоке «Что дальше» видно, кто будет проверять.
3. **Автор замечания или заказчик:**
   * «Подтвердить устранение» → «Закрыто», сохраняются кто и когда закрыл;
   * или «Вернуть на доработку» с обязательной причиной → снова «Открыто».

Если двое одновременно меняют одно замечание, второй получит «Замечание уже изменил другой пользователь».

### 3.3. Редактировать и снять

* **Редактировать** (описание, кто устраняет, срок) может автор или заказчик, пока замечание открыто.
* **Снять замечание** (например, создано по ошибке) может автор или заказчик, причина обязательна. Замечание закроется с пометкой «Снято», история останется.

### 3.4. Поиск и фильтры

* Поиск по описанию и названию задачи.
* Фильтры: этап, «Просроченные», «Мои» (где я автор или ответственный).
* Просроченное открытое замечание выделено красной полосой.

### 3.5. Фото

Фото проверяются по содержимому, геоданные удаляются. Открываются только у тех, кто видит само замечание: другой исполнитель или посторонний получит 404 даже по прямой ссылке.

---|---|
| Заказчик | Все замечания. Создаёт, закрывает, возвращает на доработку |
| Прораб | Все замечания. Отвечает, отмечает устранение |
| Исполнитель | Только замечания, где он ответственный. Отвечает, отмечает устранение |

### 3.1. Создать замечание

**Кто:** только заказчик.

**Как проверить:** «Замечания» → форма «Создать замечание» внизу страницы. Нужно выбрать этап, описать дефект, указать ответственного (прораба или исполнителя) и срок устранения. С карточки этапа в «Приёмке» кнопка «Оставить замечание» сразу подставляет нужный этап.

**Что должно запрещаться:**
* Срок в прошлом.
* Ответственный — сам заказчик.
* Этап, который ещё не начат или уже принят.
* Двойной клик: создаётся только одно замечание.

### 3.2. Устранение замечания

1. **Исполнитель** («Замечания») пишет комментарий и нажимает «Ответить» — ответ появится в ветке с автором и временем.
2. **Исполнитель или прораб** нажимает «Устранено» → статус «Устранено, ждёт проверки».
3. **Заказчик**:
   * «Подтвердить и закрыть» → «Закрыто», сохраняется кто и когда закрыл;
   * или «Не устранено» с обязательным комментарием → снова «Открыто».

Закрыть замечание может только заказчик. Если двое меняют одно замечание одновременно, второй получит сообщение «Замечание уже изменил другой пользователь».

### 3.3. Поиск и фильтры

Есть поиск по описанию, фильтры по статусу и по этапу. Просроченное открытое замечание помечается «просрочено».
