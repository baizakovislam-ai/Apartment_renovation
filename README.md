# Backend — управление проектами Бекзата, 20%

Реализован пункт Бекзата для этапа 20% по FR02: создание, просмотр, редактирование и удаление черновиков проектов. Проект хранит название, адрес, площадь, даты ремонта, бюджет, описание и фотографии. Проверяются обязательное название, положительная площадь, неотрицательный бюджет и порядок дат. Доступ к проектам и изображениям проверяется на сервере; изменять проект и управлять фотографиями может только заказчик. Удаление разрешено для черновика без этапов, фотографий, приглашений и других участников.

## Запуск в PowerShell

Из корня проекта:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe scripts/setup_postgres.py
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

Если окружения ещё нет, сначала: `py -m venv venv`.

### Общий доступ в локальной сети

Чтобы друзья подключились к вашему компьютеру через одну Wi-Fi/локальную сеть:

1. Выполните `ipconfig` и найдите IPv4-адрес активного Wi-Fi/Ethernet адаптера, например `192.168.1.25`.
2. Добавьте этот адрес в корневой `.env`, не удаляя уже имеющиеся значения:

   ```dotenv
   ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.25
   CSRF_TRUSTED_ORIGINS=http://192.168.1.25:8001
   ```

   Замените пример на ваш адрес. После изменения перезапустите сервер.
3. Запустите сервер, доступный в локальной сети:

   ```powershell
   .\.venv\Scripts\python.exe manage.py runserver 0.0.0.0:8001
   ```

   `0.0.0.0` указывается только в команде запуска: это адрес привязки сервера, его нельзя вводить в браузер.
4. Разрешите Python входящие подключения по частной сети в брандмауэре Windows, если он покажет запрос.
5. Друзья открывают `http://192.168.1.25:8001/` и входят по одному из демонстрационных email и общему паролю из таблицы ниже.

На некоторых компьютерах порт `8000` уже используется другой программой (например, IIS). В таком случае укажите свободный порт `8001` во всех трёх местах: команде запуска, `CSRF_TRUSTED_ORIGINS` и адресе в браузере.

Компьютер, на котором запущен сервер, должен оставаться включённым, а сервер — работать. Это только локальная разработка: не публикуйте `runserver` или Django admin в интернете.

### Отправка писем подтверждения через Gmail

Скопируйте `.env.example` в `.env` и укажите адрес Gmail и пароль приложения Google в `EMAIL_HOST_USER` и `EMAIL_HOST_PASSWORD`. Для пароля приложения в аккаунте Google должна быть включена двухэтапная аутентификация; обычный пароль от Gmail не подойдёт. Не отправляйте и не добавляйте `.env` в Git.

После изменения `.env` перезапустите сервер. При регистрации и восстановлении пароля на почту приходит одноразовый 6-значный код, действующий 10 минут. Для восстановления сначала укажите email на странице «Забыли пароль?», затем введите код и новый пароль. Для уже зарегистрированного, но неподтверждённого аккаунта запросите новый код на `/accounts/resend-verification/` и проверьте папку «Спам». Если отправка не удалась, аккаунт сохраняется, а ошибка SMTP записывается в консоль сервера; исправьте настройки почты и запросите код повторно. Если SMTP-переменные не настроены, письма в режиме разработки выводятся в консоль сервера.

Для входа друзей используйте три демонстрационных аккаунта (логин — email, пароль у всех общий):

| Email | Роль в демонстрационном проекте |
|---|---|
| `customer@example.com` | Заказчик |
| `foreman@example.com` | Прораб |
| `executor@example.com` | Исполнитель |

Общий пароль: `RepairDemo2026!`. Эти аккаунты предназначены только для демонстрации в доверенной локальной сети; не используйте их в боевом или публичном интернете. Создать их и демонстрационный проект в новой базе можно командой `.\venv\Scripts\python.exe manage.py seed_demo`; при запросе пароля введите `RepairDemo2026!`. Команда не перезаписывает существующие аккаунты, повторный запуск после успешного создания проекта ничего не меняет.

На этом компьютере открыть `http://127.0.0.1:8001/`; друзьям в локальной сети — `http://<IPv4-адрес-компьютера>:8001/`. Не открывайте `http://0.0.0.0:8001/`. API доступен на том же адресе по пути `/api/projects/`. Для приглашения пользователь должен иметь указанный email; регистрация и подтверждение email относятся к модулю accounts.

Используется сессионная авторизация Django. При запросах из внешнего клиента нужно передавать cookie сессии и CSRF-токен для POST/PATCH/DELETE; стандартные формы DRF делают это автоматически. Незалогиненный запрос возвращает 403, чужой проект — 404, недостаточная роль — 403, ошибка данных — 400.

## Маршруты

| Метод | URL | Доступ / действие |
|---|---|---|
| GET, POST | `/api/projects/` | Просмотр своих проектов / создание проекта с заказчиком |
| GET, PATCH, PUT, DELETE | `/api/projects/{project_id}/` | Участник читает; заказчик редактирует проект или удаляет пустой черновик |
| GET, POST | `/api/projects/{project_id}/photos/` | Просмотр фотографий / загрузка заказчиком (multipart, поле `image`, до 10 МБ) |
| DELETE | `/api/projects/{project_id}/photos/{photo_id}/` | Удаление фотографии заказчиком |
| GET | `/api/projects/{project_id}/photos/{photo_id}/file/` | Защищённое получение файла для участника проекта |
| GET | `/api/projects/{project_id}/members/` | Список участников |
| PATCH, DELETE | `/api/projects/{project_id}/members/{member_id}/` | Только заказчик; изменение роли / удаление |
| GET, POST | `/api/projects/{project_id}/invitations/` | Только заказчик; список / приглашение |
| POST | `/api/projects/{project_id}/invitations/{invitation_id}/cancel/` | Отмена приглашения заказчиком |
| POST | `/api/invitations/{token}/accept/` | Аккаунт с email из приглашения |
| GET | `/api/projects/{project_id}/events/` | История; заказчик и прораб |
| GET, POST | `/api/projects/{project_id}/stages/` | Чтение участниками; создание заказчиком или прорабом |
| GET, PATCH, DELETE | `/api/stages/{stage_id}/` | Чтение участниками; изменение менеджерами; удаление автором черновика |

Списки возвращаются как JSON-массивы, без пагинации.

### Создать проект

```json
{
  "name": "Ремонт квартиры",
  "address": "г. Бишкек, ул. Примерная, 10",
  "area": "68.50",
  "start_date": "2026-10-20",
  "end_date": "2026-12-20",
  "budget": "1500000.00",
  "description": "Косметический ремонт квартиры"
}
```

Создатель автоматически становится единственным заказчиком. Поля кроме названия необязательны. `area` должна быть больше нуля, `budget` не может быть отрицательным, а дата окончания должна быть не раньше даты начала. Фотографии загружаются отдельно на `/api/projects/{project_id}/photos/`; допускаются изображения до 10 МБ. Ссылки на изображения ведут на защищённый маршрут и работают только для участника проекта.

Удаление проекта доступно заказчику только пока в проекте нет этапов, фотографий, приглашений и других участников. При наличии связанных данных API возвращает ошибку, чтобы не потерять рабочую информацию.

### Пригласить участника

```json
{"email": "foreman@example.com", "role": "foreman"}
```

Роли: `customer`, `foreman`, `executor`. Пригласить и назначить можно прораба или исполнителя. Заказчика изменить или удалить нельзя. Один пользователь имеет одну роль в одном проекте, но может иметь разные роли в разных проектах. Один прораб на проект; одновременно допускается только одно ожидающее приглашение прорабу. До принятия приглашения доступа нет.

Токен возвращается заказчику в ответе. Его нужно передать получателю, который выполняет POST на маршрут принятия из своего аккаунта. Токен одноразовый, действует 7 дней. Автоматическая доставка приглашения по email в этом этапе не реализована. Истёкшее приглашение не даёт доступа и не мешает создать новое.

### Изменить роль

```json
{"role": "executor"}
```

Перед удалением участника или изменением его роли сначала переназначьте этапы, за которые он отвечает.

### Создать этап

```json
{
  "name": "Электрика",
  "description": "Прокладка кабеля",
  "start_date": "2026-10-20",
  "end_date": "2026-10-25",
  "responsible": 2,
  "position": 1
}
```

`responsible` — ID записи ProjectMember, **не ID пользователя**. Взять его из списка участников. Начало и конец обязательны, окончание не раньше начала. PATCH поддерживает частичное обновление. Проект и автор назначаются сервером.

Новый этап имеет статус `planned`. Реализованы переходы `planned → in_progress → completed`, возврат `completed → in_progress`. Статус `completed` означает выполнение работ, а не приёмку заказчиком. Статусы `pending_acceptance`, `accepted`, `cancelled` зарезервированы для дальнейшей интеграции; присвоить их через этот API нельзя. Этапы в этих статусах не редактируются. Полный запуск ремонта с проверкой утверждённой сметы должен быть подключён позже вместе с жизненным циклом проекта.

Удалить можно только собственный этап в статусе planned без зависимых записей. История действий остаётся после удаления этапа и участника.

## Границы для команды

- `apps.projects.models.Project` — общая точка связи с проектом; управление проектными полями для этапа 20% реализовано в этой модели и её API.
- Пользователь — `settings.AUTH_USER_MODEL` (сейчас встроенный пользователь Django). Если нужна кастомная модель, переход требует отдельного согласования миграций.
- `ProjectMember` — источник ролей. Общие проверки в `apps.projects.permissions`.
- Все изменения участников и этапов проводить через `services.py`, чтобы сохранить проверки, транзакции и историю.
- `Stage` находится в `apps.repairs.models`. Будущие задачи, финансовые записи и приёмка должны ссылаться на него; важные связи защищать через `on_delete=PROTECT`.
- На этапе сдачи 20% поставляется управление проектами Бекзата и текущие части Ислама и Абдулазиса. Приёмка, финансы, средняя стоимость и завершение проекта Бекзата относятся к последующим контрольным этапам из графика.
- Нет автоматического письма-приглашения, Swagger, фонового планировщика и полного жизненного цикла проекта (активация, архивирование и редактирование дополнительных реквизитов).
- Время хранится Django с timezone, часовой пояс отображения — Asia/Bishkek.
- Мутации блокируют строку проекта внутри транзакции; SQLite не поддерживает блокировки SELECT FOR UPDATE. Для параллельной работы общего сервера нужна БД с поддержкой таких блокировок, например PostgreSQL. Уникальность участников и ролей также защищена ограничениями БД.

## Подключённый интерфейс

Файлы находятся в `apps/workspace/`. Дизайн перенесён из предоставленного React-макета в Django-шаблоны. Цвета, боковое меню, карточки, временная шкала этапов и стили форм сохранены; Node.js и отдельный frontend-сервер не нужны. Исходные файлы .figma, конфигурация Vite и инструкции из архива не исполнялись и не переносились. `design.css` содержит стили макета без импорта Tailwind, `app.css` — адаптацию и улучшение читаемости, `app.js` — мобильное меню, подтверждение удаления и копирование ссылок.

| Адрес | Назначение |
|---|---|
| `/` | Рабочая панель с данными выбранного проекта |
| `/projects/` | Мои проекты и поиск по названию |
| `/projects/new/` | Создание проекта |
| `/projects/{id}/stages/` | Этапы, поиск и фильтр по статусу |
| `/projects/{id}/stages/new/` | Создание этапа |
| `/projects/{id}/stages/{stage_id}/edit/` | Редактирование этапа |
| `/projects/{id}/members/` | Команда, изменение ролей, удаление, создание и отмена приглашений |
| `/invitations/{token}/` | Просмотр и принятие приглашения своим аккаунтом |
| `/projects/{id}/history/` | История для заказчика и прораба |
| `/accounts/login/`, `/accounts/register/` | Вход и регистрация в новом оформлении |
| `/accounts/profile/` | Профиль и переход к рабочей панели |

Формы вызывают существующие сервисы и соблюдают те же ограничения, что API. Все изменения — POST с CSRF-токеном. Роль берётся из ProjectMember, переключателя чужих ролей в интерфейсе нет. Работают настоящие данные; цифры бюджета, фото и задачи из макета не используются. В интерфейсе представлены только доступные функции: пользователи, минимальная основа проекта, участники, приглашения, этапы и история. Остальные экраны макета подключаются по мере появления модулей. Для проекта сейчас доступно только название; описание полного FR02 выше требует соответствующего backend, которого в текущей модели ещё нет.

После регистрации email нужно подтвердить. В локальной конфигурации письмо выводится в терминал; скопируйте ссылку подтверждения. Вход в демонстрационные аккаунты уже разрешён. Приглашение создаётся на странице участников: скопируйте ссылку и откройте её под аккаунтом получателя, затем нажмите «Принять приглашение».

Для проекта с уже существующей базой, созданной до установки `AUTH_USER_MODEL = "accounts.User"`, обычного migrate недостаточно. Не удаляйте базу с данными; сначала сохраните копию и выполните отдельный перенос пользователей и ссылок. В этой локальной рабочей папке старая база была проверена как пустая, сохранена в `db.sqlite3.before-email-user.*.bak`, затем новая создана миграциями. Резервные базы исключены из Git.
